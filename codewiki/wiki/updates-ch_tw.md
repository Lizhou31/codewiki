## 更新流程 {#flow}

更新會選擇既有實例、安裝所需框架，再啟動新的 Python 程序，以新安裝套件整合支援檔案。`--installed` 直接從整合階段開始。命令與衝突解決方式請見[更新手冊](manual-updating.html)。

## 發佈版與原始碼安裝 {#release}

`update.main()` 透過 `sys.executable` 執行 pip；沒有 pip 時，改用 uv 並指定 `--python`。預設向設定的索引取得名稱為 `codewiki-framework` 的套件；`--source` 則為含 `pyproject.toml` 的本機工作目錄建立具名直接參照，由安裝程式驗證套件名稱。不會執行 Git 命令或猜測遠端儲存庫。

安裝會強制替換，讓相同版本的原始碼建置也能更新已安裝程式。Pip 可能重新安裝相依套件；uv 只強制重新安裝 CodeWiki。子程序使用暫存工作目錄與參數串列，不使用 shell 字串。新程序以絕對設定路徑與專案路徑執行 `python -m codewiki update --installed`，載入新實作。安裝失敗就不進行整合，子程序失敗則傳回其結束碼。環境與實例是兩個獨立修改階段，不是單一交易。

## 選擇既有實例 {#selection}

設定探索與其他 CLI 命令共用。Manifest 記錄相對於實例的專案根目錄；舊的慣用資料夾會推定其父目錄，有歧義的配置則需指定 `--root`。實例必須位於專案內，Wiki 目錄必須位於實例內。寫入前會拒絕受管理路徑中的符號連結、向上跳脫，以及檔案與目錄衝突。

## 追蹤套件基準 {#baselines}

`init` 在 `.codewiki-manifest.json` 記錄與目前套件內容相同檔案的 SHA-256 雜湊。既有客製化檔案不會被當成套件副本。重複初始化會保留先前基準。格式錯誤或不支援的 manifest 會導致失敗，不會靜默重設檔案歸屬資訊。Manifest 與專案一起提交，只有完整整合後才記錄新的框架版本。

## 整合支援檔案 {#files}

共用清單包含技能、整合範例、範本、標籤指南與實例代理指南，並遵循設定的 `wiki_dir` 及相對於專案的實例路徑。已撰寫頁面、設定、主題、審查紀錄與產生的輸出不在此清單中。套件已移除的檔案不會從專案刪除。

完全相同的檔案會建立目前套件雜湊；缺少檔案會補入。本機位元組符合先前套件雜湊時，新版會替換它；套件雜湊未變時，則保留本機客製化。兩者都不同時，保留本機內容並將新版放到 `.codewiki-update/`。來源不明的舊檔案也走同樣保守的衝突流程。

比較後，可透過 `--installed` 搭配 `--keep-local`，明確確認保留或合併的檔案已考量新版套件雜湊。它不覆寫本機文字，未來套件變更仍可能再次產生衝突。尚有衝突時保留先前完成版本，但已成功處理的個別檔案基準可前進。每個檔案與 manifest 的替換是原子操作，整批更新則不是。整合後使用初始化程式的單次附加函式補入根目錄代理指示，不重寫既有參照區段。預覽不寫入檔案，也不安裝套件。

## 驗證 {#tests}

`tests/test_update.py` 以隔離實例與替代套件資源驗證支援檔案升級、專案內容保護、重複執行、客製化與舊檔案、明確的合併確認、自訂 Wiki 目錄、無效 manifest，以及符號連結與父目錄為檔案的拒絕行為。安裝測試不連線到真實套件索引，檢查 Python 選擇、本機原始碼參照、預覽、失敗傳遞與新程序派送。另以已建置 wheel 的基本檢查，在不同目錄實際執行安裝、初始化、更新與嚴格建置。
